# 01 — Decode the Hackathon

## WHAT
Before ideating, extract the **game board**: theme, constraints, judges, sponsors, time, team.

## WHY
Winning ideas fit the judging rubric and sponsor story — not just "cool tech."

## HOW — decode checklist
| Lens | Questions |
|---|---|
| Theme | What nouns/verbs are required vs optional? |
| Required tech | Must-use vs nice-to-use? |
| Sponsors | Which APIs pay off in judging? What is a forced bolt-on? |
| Judging | Innovation / impact / design / tech / demo — weights? |
| Users | Who could be the hero of the story in 60s? |
| Problem spaces | Adjacent pains under the theme |
| Constraints | Offline? Privacy? Hardware? Age? Region? |
| Time | 6 / 12 / 24 / 36 hours? |
| Team | FE/BE/AI/design strength |

### Hidden opportunities
- Underserved user in the theme (ops, not consumer)
- Workflow between two sponsor tools
- Boring pain with spectacular demo transform
- Real-time / multimodal if others ship chat UIs

## FAILURE MODE
Ideating before reading the rubric → beautiful product that scores 0 on "uses sponsor X."

## DEBUGGING (meta)
If stuck: re-read judging criteria aloud; kill ideas that don't map to a criterion.

## AI USE
Paste prompt + rubric into an agent with `prompts/hackathon/decode-prompt.md` — then **you** challenge outputs.
